# AI Use Log

## Sources Reviewed

This log was prepared by reviewing the repository history, recent commit messages, changed files, and the current portfolio structure. The review included the `portfolio/` pages, prototype documentation, evaluation page, references page AI disclosure, live app / QR code references, GitHub links, and recent changes to the demo app pages.

## Tools Used

- ChatGPT / Codex for implementation support, wording refinement, debugging guidance, and portfolio organization.
- VS Code for editing, reviewing files, and checking the project structure.
- Git for reviewing history, changed files, and repository state.

## Main AI-Assisted Activities

- Portfolio structure and navigation refinement across the main pages.
- HTML/CSS layout support for responsive cards, tables, case-study sections, and visual consistency.
- Wording refinement for portfolio explanations, AI disclosure, evaluation reflection, and contribution summaries.
- Debugging support for app pages and portfolio issues, including layout density, incorrect image paths, placeholder screenshots, and repository links.
- Git and deployment troubleshooting support, including checking changed files, GitHub repository links, live app references, and QR code placement.
- Alignment checks between requirements, prototype features, evaluation evidence, and the final three features: personalized route recommendation, DIY route creation, and community sharing.

Because exact prompt transcripts were not retained for every interaction, this section records the main prompt types and AI-assisted tasks rather than verbatim conversations.

## Example Prompt Types

- Summarize how a portfolio page should be reorganized to better match CPT208 submission requirements.
- Improve responsive HTML/CSS layout for a portfolio section while keeping the existing ClimbQuest visual style.
- Help debug a broken image path or placeholder screenshot reference in the portfolio.
- Refine wording for evaluation findings, AI disclosure, or team contribution descriptions.
- Check whether prototype, evaluation, and requirements sections are aligned with the final feature set.
- Review Git history or changed files to understand what project areas were recently modified.
- Update repository links, live app references, and portfolio checklist items without changing page layout.

## Problems Encountered

- Some AI suggestions introduced ideas outside the final project scope, such as extra coaching or badge-style features, so these were filtered out.
- Some draft content mixed Research, Users, Ideation, Prototype, and Evaluation material, so sections had to be separated and checked manually.
- Several layout drafts were too dense or visually heavy and needed manual refinement for spacing, card size, and mobile responsiveness.
- Some asset references needed correction, including placeholder screenshots, duplicated image extensions, and final evaluation image paths.
- Repository links and page anchors needed checking to avoid outdated or inconsistent references.

## Verification

The team manually checked AI-assisted work against CPT208 requirements, poster data, survey and evaluation numbers, personas, user journey evidence, and the final three features. We also verified the live app link, QR code, GitHub repository links, image paths, academic reference anchors, and responsive page layouts. AI-assisted wording was reviewed against the team's own research evidence and final design decisions before being included.

## Reflection

AI was useful for scaffolding page structure, improving wording, debugging HTML/CSS issues, and organizing portfolio evidence. However, it was used as a support tool rather than a design decision-maker. The team remained responsible for user research, survey interpretation, personas, evaluation scores, ethical judgement, design reasoning, and final content decisions.
