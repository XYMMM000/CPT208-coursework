P02 From Low-Fi to High-Fi

From Low-Fidelity Wireframes to Prototype Structure

After selecting ClimbQuest as the final concept, we translated the three core flows into low-fidelity mobile wireframes. These wireframes helped us test navigation, screen hierarchy, and how users move between recommendation, DIY creation, and community interaction before applying visual design.

P03 Feature 1

Personalized Route Recommendation

Linked to DG1: Reduce route-selection uncertainty

User Need: Users often feel unsure about which route fits their ability, confidence, preferred climbing style, or training goal.

Prototype Flow: The prototype guides users through a playful MBTI-style questionnaire. Based on their answers, the system presents a climbing type result and recommends suitable routes.

Key Screens
  • Quiz Screen
  • Climbing Type Result
  • Recommended Routes
Key Interactions
  • Select quiz answers
  • Generate a climbing type result
  • View recommended routes
  • Open route details
  • Choose "Try this route"
Flow Logic
Quiz->Type->Routes->Detail
Human-Centred Value: This feature reduces decision pressure and helps users start climbing with clearer, more personalised guidance.
P04 Feature 2

DIY Route Creation

Linked to DG2: Increase creative ownership

User Need: Some users want more autonomy and creative involvement instead of only completing routes designed by others.

Prototype Flow: Users create a route by selecting holds on a wall image, connecting a route path, and adding route information such as name, difficulty, style, and description.

Key Screens
  • Wall Image / Hold Selection
  • Route Path Preview
  • Route Details Form
  • Save or Upload Route
Key Interactions
  • Select holds on the wall image
  • Connect selected holds into a route path
  • Undo, erase, or clear selections
  • Add name, difficulty, style, and description
  • Save draft or upload route
Flow Logic
Holds->Path->Details->Upload
Human-Centred Value: This feature turns users from route followers into route creators, making the climbing experience more participatory and playful.
P05 Feature 3

Community Sharing & Interaction

Linked to DG3: Support social motivation

User Need: Users may lose motivation when climbing alone or when their climbing session ends without feedback, discovery, or follow-up.

Prototype Flow: The community flow allows users to browse routes shared by others, open route details, like and comment on routes, and choose routes to try.

Key Screens
  • Community Feed
  • Shared Route Detail
  • Like / Comment Interaction
  • Try Route Action
Key Interactions
  • Browse shared routes
  • Search or filter routes
  • Like a route
  • Comment on a route
  • Try a shared route
  • Upload user-created routes
Flow Logic
Browse->React->Try->Share
Human-Centred Value: This feature extends the climbing experience beyond a single session and supports motivation through peer-generated challenges.
P06 System Architecture

Interaction Logic and Data Flows

Recommendation Logic

Quiz Answers->Matching Rules->Recommended Routes

DIY Route Object

Wall Image + Selected Holds->Route Object->Saved / Uploaded Route

Community Interaction State

Uploaded Routes->Community Feed->Likes / Comments / Tries

The current prototype uses front-end state to demonstrate the intended interaction logic. Quiz answers are mapped to route recommendation results, selected holds form a DIY route object, and community actions such as likes, comments, and tries update the route interaction state. This allows users to experience the main system logic before full backend implementation.

P09 Technical Reflection

AI-Assisted Development

Tools Used

ChatGPT, Codex, VS Code, GitHub

How AI Assisted

  • Generated initial component structures
  • Helped debug layout and responsive CSS
  • Suggested portfolio wording and section organization
  • Supported image placement and Git workflow troubleshooting

How We Verified the Work

  • Tested each core user flow manually
  • Checked image paths and responsive layouts
  • Compared prototype features with user requirements
  • Reviewed readability, button clarity, and mobile usability
Ethical Considerations: AI was used as implementation and communication support, while the user research, design requirements, and final design decisions remained group-owned. AI-generated or AI-assisted assets are acknowledged where appropriate, and no fabricated user data was used.
