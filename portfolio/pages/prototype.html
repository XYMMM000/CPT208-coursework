01 System Architecture

Mobile-First Prototype Structure

ClimbQuest is a mobile-first web prototype connecting three core flows: Personalized Route Recommendation, DIY Route Creation, and Community Sharing & Interaction.

Frontend / Interface

Mobile web app, quiz interface, DIY route editor, community feed, and route detail pages.

Data / State

Quiz answers, recommendation result, selected holds, route metadata, likes, comments, and try actions.

Deployment

Vercel live app and GitHub repository for access, review, and version control.

02 Data Flow

Core Interaction Flows

Recommendation Flow

Quiz Answers->Matching Logic->Climbing Type->Recommended Route

DIY Creation Flow

Wall Image->Selected Holds->Route Path->Route Metadata->Saved / Uploaded Route

Community Flow

Uploaded Route->Community Feed->Like / Comment / Try->Updated Route Detail

05 System Features

From Design to Implementation

SF1

Personalized Route Recommendation

Implements DG1 -> R1: Reduce route-selection uncertainty

Linked evidence: users were unsure which route fits them.

What it does

Users complete a playful quiz and receive route suggestions based on preference, confidence, and goals.

Technical / Interaction Implementation
  • Quiz answer selection
  • Rule-based matching logic
  • Climbing type result
  • Recommended route list
  • Route detail entry point
UX Outcome
  • Helps users start with clearer guidance
  • Reduces route-selection pressure
  • Makes recommendations feel playful and personal
SF2

DIY Route Creation

Implements DG2 -> R2: Increase creative ownership

Linked evidence: users wanted more autonomy and creative involvement.

What it does

Users select holds on a wall image, connect them into a route path, and add route details.

Technical / Interaction Implementation
  • Wall image display
  • Hold selection
  • Route path preview
  • Route metadata form
  • Save / upload action
UX Outcome
  • Turns users from route followers into route creators
  • Encourages creative participation
  • Supports playful route-making
SF3

Community Sharing & Interaction

Implements DG3 -> R3: Support social motivation

Linked evidence: users lacked motivation and peer feedback.

What it does

Users browse routes shared by others, open route details, like/comment, and try shared routes.

Technical / Interaction Implementation
  • Community route feed
  • Route detail cards
  • Like/comment interaction
  • Try route action
  • Shared route upload logic
UX Outcome
  • Extends motivation beyond one climbing session
  • Supports peer feedback
  • Makes routes discoverable and reusable
